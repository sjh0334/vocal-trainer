# F001: 听见你的声音

> **Status**: implementation_review | **Owner**: 砚砚 | **Priority**: P1

## Why

用户需要一个真正能指导练习的 Web 工具：实时检测演唱音高，与目标旋律比较“准 / 偏高 / 偏低”，练完后用可信的分项评分说明问题和下一步练法。README 明确要求先把“音高检测准、实时反馈直观、评分能指路”这三个地基做扎实，而不是堆叠曲库、社交或 AI 噱头。

## Implementation Baseline / 实施起点

- 仓库基线只有初始提交 `80c7145`；需求当前记录在 `README.md`。
- 2026-08-07 曾生成一版未确认的 Web 脚手架与约 950 行实现。operator 明确要求删除，现已从主仓库移除，未作为实现基线继承。
- 因此本轮从没有可运行 Web App、测试、音频夹具或已验证评分实现的干净基线启动。

## What

### Phase A: 音频与音高地基

- 建立原生 JavaScript Web App 的测试与构建环境。
- 使用单声道 Web Audio 采集和 YIN 基频检测。
- 将采集、算法和 UI 渲染拆到明确边界，避免检测计算阻塞页面。
- 建立合成音频与录制人声夹具，先证明准确率、置信度门禁和资源释放。

### Phase B: 简单旋律、练习准备与实时跑道

- 内置少量版本化的简单旋律练习；选择后先进入练习准备页，由用户分别触发试听和开始练习。
- 示范音采用柔和音色、低增益与渐入渐出，避免突兀、刺耳的听感。
- Canvas 同时展示目标音符块、用户音高轨迹、中央游标和“准 / 高 / 低”文字反馈。
- 完成权限、环境检测、倒计时、练习、结束和错误恢复的单一会话状态机。

### Phase C: 评分、报告与录音回放

- 按稳定度 40%、音准 30%、气息连续性 20%、音量衰减 10% 生成可解释报告。
- 录音与音高检测共用同一麦克风会话；练习结束后可回放本次录音，并让播放游标与音高轨迹对齐。
- 报告、音高轨迹和录音 Blob 仅保存在浏览器本地 IndexedDB，默认永久保存，并支持单条及全部删除。
- 保持 PWA-ready，但核心闭环验收前不引入 Service Worker。

## User Journey

### Primary Journey: 跟着简单旋律完成一次练习并回听

- **Scope unit**: session
- **Actor**: 练歌用户
- **Entry**: 打开 Web App 的练习选择页
- **Flow**:
  1. 用户选择一条内置简单旋律，进入练习准备页，查看音域和时长，并可先试听示范；此时不请求麦克风。
  2. 用户明确点击“开始练习”后，App 才请求麦克风权限，并检查输入音量和环境噪声。
  3. 倒计时结束后，用户看着跑道演唱；App 实时显示目标音符、用户轨迹和准/高/低反馈。
  4. 旋律结束或用户主动结束后，App 释放麦克风并生成四项评分、原始指标和练习建议。
  5. 用户播放本次录音；播放游标与保存的音高轨迹同步移动。
  6. 用户可再次练习、查看历史报告或删除本地录音及报告。
- **Success evidence**: 浏览器端到端录屏、报告截图、回放与轨迹游标同步测试
- **Non-goals**: 完整歌曲/歌词/伴奏版权系统、歌曲主旋律自动提取、账号与云同步、社交排行、AI 音色或共鸣诊断、首版 PWA 安装交付

## Acceptance Criteria

<!-- 每条 AC 必须 trace 回 Why，并可由非作者通过测试、浏览器证据或数据复核。 -->

### Phase A（音频与音高地基）

- [x] AC-A1: 约 82–880 Hz 的清洁正弦及含谐波测试夹具中，有效帧的中位音高误差不超过 5 cents；测试命令和完整频点结果可复核。
- [x] AC-A2: 静音、低能量噪声和低置信度帧不进入评分；夹具测试覆盖 false-positive 与 voiced/unvoiced 边界。
- [x] AC-A3: 任一时刻最多存在一个活动麦克风流；拒绝权限、快速双击开始、设备中断、页面退出和 Worker 故障均会释放 MediaStream、AudioContext、Worker 与录音器。

### Phase B（简单旋律、练习准备与实时跑道）

- [x] AC-B1: 用户可选择至少两条版本化的内置简单旋律；选择后进入独立练习准备页，可试听柔和示范音；只有明确点击“开始练习”才进入环境检查、倒计时和练习，进入准备页不得请求麦克风。
- [x] AC-B2: Canvas 在同一时间轴显示目标音符、用户音高、游标及非纯颜色的准/高/低反馈；窄屏和桌面截图均可读。
- [ ] AC-B3: 在约定的基准设备和浏览器上，音频输入到视觉反馈的 p95 延迟不超过 150 ms，且渲染不阻塞音高检测。

### Phase C（评分、报告与录音回放）

- [x] AC-C1: 音准按每个目标音符的“带符号平均偏差取绝对值”计算；对称颤音主要降低稳定度而非音准，恒定偏移会降低音准，均有回归测试。
- [x] AC-C2: 报告展示总分、四项分数、原始指标、数据质量和至少一条可追溯诊断；有效发声不足时明确显示“数据不足”而不生成误导性总分。
- [x] AC-C3: 一次练习只生成一个录音记录；结束后可本地回放，播放游标与音高轨迹同步，刷新页面后记录仍可恢复。
- [x] AC-C4: 录音、报告和轨迹不上传，默认 TTL=0；用户可删除单条或全部本地记录，删除后 Blob URL、数据库记录和关联元数据均不可再访问。
- [ ] AC-C5: App 在桌面 Chromium 和 Android Chrome 完成真实麦克风验收；iOS Safari 的支持状态有独立实测结论，不以推测宣称兼容。
- [x] AC-C6: Web App 具备响应式应用壳、本地数据边界和可缓存静态资源边界，但首版不注册 Service Worker。

## Risk

| 风险 | 缓解 |
|------|------|
| 浏览器、设备和麦克风导致音高与延迟差异 | 合成夹具 + 真实人声夹具 + 基准设备实测；报告暴露数据质量 |
| UI 平滑掩盖真实抖动并虚增稳定度 | 显示平滑与评分数据流分离，评分只用质量门后的原始帧 |
| 播放示范音被麦克风重新采集 | 试听与录音分阶段；录音前停止示范音并清空检测缓冲 |
| 录音 Blob 占用本地空间 | 展示记录大小和存储错误，支持单条/全部删除，不静默丢数据 |
| 浏览器崩溃留下半成品会话 | 会话单 owner；录音完成后原子保存，启动时清理未提交会话 |
| 分数阈值缺少真实人声校准 | 阈值配置版本化，保留原始指标，用已标注人声夹具校准后再锁定 |
